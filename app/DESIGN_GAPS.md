# App adapters and remaining design gaps

The published design system and the Python pipeline are read-only. The app composes their existing components and records runtime adapters here. App layout, motion, charts, fonts, colours and focus treatment use the supplied tokens; procedural fixture images come from the supplied scene generator.

| Gap in the showcase | App implementation |
| --- | --- |
| No executable app, generated token sheet or global React bootstrap | Vite app, `react-global.ts` before any DS import, `scripts/build-tokens.mjs`, local font assets and the Tailwind 3 preset |
| `components/index.d.ts` contains implementation text as well as declarations and cannot be consumed as a valid declaration file | A narrow ambient module boundary in `src/ds.d.ts`; app event/domain/data-source types remain strict. DS props are adapted at that boundary. A clean upstream declaration package would remove the remaining `any` adapter surface |
| Showcase scenes instead of actual images | `Strip`, `Viewer`, `Crop` retain the `PanoramaStrip`, `Viewer360` and `ZoomCrop` frames while supplying the local, decoded panorama. Pannellum uses the existing canvas; full-resolution crops are cut on demand |
| The screenshot examples assume a complete case record | App adapters preserve missing uncertainty, support, boxes, fallback names, residency, counts and intervals. They suppress example-only numbers and label missing information. Zero is retained only when it was actually logged |
| `CaptionBar` was primarily laid out for the full-width stage; a long model chip squeezes its headline into a narrow column | The console column stacks the original caption's source/time row below its headline and sentence, using token gaps. Stage and full-width captions retain the supplied composition. Both announce with `aria-live` |
| `LeaderLines` only remeasures on selection and window resize | `LinkedView` supplies a layout revision on event arrival and column scroll, linking the existing pixels, evidence card and map anchors |
| No live MapLibre adapter | `EvidenceMap` composes `MapView` and its legend with MapLibre for local tiles. It supplies actual logged heat cells, points, zones, rings and reference GPS in the fixed layer order; missing/failed tiles use the existing bundled outlines |
| Showcase maps synthesize decorative heat/samples from complete example cases | The app replaces those layers with logged cells and sampled points. No random points or invented heat are used for live/minimal logs |
| Unknown region IDs or geometry-free questions cannot use the showcase's named regions | Proposed GeoJSON Polygon outer rings are drawn when supplied. Known bundled region IDs remain supported. No geometry produces no zone. Holes and MultiPolygon zones remain an integration extension |
| No Compare screen | `Compare` composes `CandidateRow`, `Viewer360` / `ZoomCrop`, `MatchView`, `Stamp`, `EvidenceMatrix`, `PolarityChip`, `ScoreCurve` and the existing look-alike layout. Local reference assets and logged normalized keypoints replace example geometry |
| The showcase displays all diagnostics and history at once; it has no disclosure primitive | App-owned, token-styled native `details` / `summary` controls provide keyboard-accessible disclosure. The console defaults to one photo view, one current evidence card and three leading candidates. Full evidence, stages, matrix and log remain in tabs; candidate sources, ranges, changes and ruled-out reasons remain in Candidate details. Run metrics, replay timeline, photo tools, receipts and answer history are expandable. Compare keeps its photo pair visible and folds its matrix, score curve and share links. Completed question zones can be restored through Map key; open questions and costs stay visible. No event data, penalty or answer state is changed |
| Match projection and mask palette conventions were unspecified | `CONTRACT.md` proposes an explicit query FOV and normalized keypoint pairs. Class-indexed PNG masks are decoded once and mapped to theme tokens; `mask_palette` allows a pipeline-specific class order |
| Beats 4–7 have no motion key-frame pages | `src/motion.ts` supplies event-triggered sign/crop, checklist, segmentation/sun and retrieval motion using tokens and SVG. All twelve beats are mapped to real event types. Reduced motion uses quick fades and cuts map flights |
| Showcase buttons/slider do not expose all runtime callbacks | App wrappers wire upload, replay, questions, cues, exports, submission and comparison controls without changing the DS sources |
| Showcase Tabs/Segmented and dialogs omit full keyboard handling | The app adds arrow/Home/End selection, focus trapping/restoration, Escape, reference arrows and the task's keyboard map. Interactive evidence/matrix/map marks receive keyboard access |
| Showcase matrix totals count correlated rows repeatedly | The app footer counts each correlated group once, separately for supporting and contradicting sources |
| Queue examples include stage/gain metadata and complete sample rows | `QueueCard` retains the sealed `CaseCard` and shows status only. It hides incomplete/example-only metadata. Invalid uploads remain in intake, outside the worker queue |
| Sample run has no JPEG | The strip shows “Panorama file not available for this log” and does not substitute an invented scene for that real log |
| No stage synchronization or live submission interface | A per-console BroadcastChannel carries exactly one active case and its replay/animation state. `submit` and `priority` endpoints are proposed in the contract; the mock audits them |

Motion is a frontend implementation against the log contract, not a simulation of inference. The fixture run exercises all twelve event mappings. Detailed timing with real mask/reference latency, dense detection batches and venue hardware remains to be verified when those pipeline events and assets exist. Loading an asynchronous mask preserves its logged geometry; its tint arrival currently follows asset availability, so the pipeline should serve masks before emitting the observation for the intended sweep timing.

The main remaining design integrations are matching a different query projection/aspect ratio, geographic Polygon holes/MultiPolygons, and projector legibility with the venue's actual display and tile extract. These do not introduce fabricated pixels, coordinates or uncertainty while the inference package is absent.
